# Бот MAX: карта интерфейса

Всё, что видит пользователь: экраны, кнопки, payload'ы, состояния и
тон. Код — `bot/`, тексты — `bot/texts.py`, клавиатуры — `bot/keyboards.py`.

---

## 1. Главное меню

Приветствие приходит один раз: MAX шлёт событие `bot_started` при
добавлении бота и команду `/start` следом. Оба хендлера отвечали бы
приветствием, поэтому `cmd_start` пропускает сообщение, если флаг
`welcomed` уже выставлен (`bot/handlers/start.py`).

```text
🎯 Цель            goal:show
🧠 Диагностика     as:start
🎮 Миссия          ms:next
📊 Skill Map       sm:show
📚 Курсы           cr:rec      💼 Стажировки   in:rec
📄 Резюме          rs:start
ℹ️ Инструкция      help:show
```

| Payload | Экран |
|---|---|
| `goal:show` | список целевых ролей |
| `as:start` | первая вопроса диагностики |
| `ms:next` | следующая миссия по цели |
| `sm:show` | Skill Map |
| `cr:rec` | курсы по пробелам |
| `in:rec` | стажировки по направлению |
| `rs:start` | согласие на ПД, затем приём резюме |
| `help:show` | инструкция |
| `menu:main` | возврат в главное меню |

## 2. Все payload'ы

| Payload | Обработчик | Смысл |
|---|---|---|
| `goal:show` | `goal.goal_show` | список ролей |
| `goal:pick:{role_id}` | `goal.goal_pick` | выбрать цель |
| `as:start` | `assessment.start_assessment` | начать диагностику |
| `asq:{question_id}:{option_index}` | `assessment.assessment_answer` | ответить на вопрос |
| `ms:next` | `missions.mission_next` | следующая миссия |
| `ms:ans:{mission_id}:{option_id}` | `missions.mission_answer` | ответить на миссию |
| `sm:show` | `skillmap.show_skill_map` | Skill Map |
| `cr:rec` | `recommend.recommended_courses` | курсы по пробелам |
| `cr:page:{n}` | `recommend.recommended_courses` | страница курсов (тот же хендлер) |
| `in:rec` | `recommend.internship_filters` | экран выбора направления |
| `in:dir:{direction}` | `recommend.internships_by_direction` | стажировки по направлению |
| `in:dir:{direction}:{page}` | `recommend.internships_by_direction` | направление и страница (тот же хендлер) |
| `in:dir:any` | `recommend.internships_by_direction` | без фильтра по направлению |
| `rs:start` | `resume.ask_resume` | резюме: согласие, затем приём |
| `rs:consent:yes` | `resume.accept_consent` | согласие на обработку ПД |
| `rs:consent:no` | `resume.decline_consent` | отказ |
| `rs:consent:revoke` | `resume.revoke_consent` | отзыв согласия |
| `rs:policy` | `resume.show_policy` | текст политики |
| `rs:cancel` | `resume.cancel_resume` | отменить ожидание резюме |
| `help:show` | `start.show_help` | инструкция |
| `menu:main` | `start.back_to_menu` | главное меню |

Правила формирования:

- префикс двумя буквами + `:` — `go`/`as`/`ms`/`sm`/`cr`/`in`/`rs`;
- порядок параметров слева направо, каждый — одно значение;
- `option_index` и `option_id` — разные вещи: в диагностике это позиция
  варианта в банке вопросов, в миссии — идентификатор варианта в базе;
- `any` — зарезервированное значение, означающее «без фильтра»;
- бейджи ответов: `①`…`⑩` (десять позиций), дальше — обычные цифры;
- вариативные payload'ы разбираются префиксом
  (`F.callback.payload.startswith(...)`) и парсятся вручную, поэтому
  битый payload молча игнорируется, а не роняет хендлер.

## 3. Экраны

### Цель

`goal:show` → список ролей кнопками `goal:pick:{id}` + «🏠 Меню».
Пустой каталог → «Ролей пока нет».

`goal:pick:{id}` → сохраняет цель, показывает gap-анализ: процент
соответствия, что не хватает (до 6 позиций), что уже в норме, и главное
меню для следующего шага.

Роль не выбрана → «🎯 Сначала выбери цель» с кнопкой `goal:show`
(`goal_required_kb`). Показывается в диагностике и миссиях.

### Диагностика

Вопросы подбираются под направление: универсальные показываются всем,
остальные — только если навык релевантен направлению целевой роли или
`user.direction`. Неизвестное направление → весь банк.

Состояние — `sessions[uid]["answers"]`, список
`{"question_id", "option_index"}`. Экран: `📌 Навык: <name>`,
`Вопрос N/M`, текст, пронумерованные варианты, кнопки-бейджи.

Смена направления сбрасывает прогресс: `set_initial_skill` берёт
`max(текущий опыт, порог)`, поэтому переоценка вниз не откатывает
уровень. Завершение → «Диагностика завершена» + сводка + главное меню;
`answers` очищается.

### Миссия

Требует цели. Без неё — экран `goal_required_kb`.

Заголовок: `🎮 Миссия {done+1}/{total} по цели · <навык> · <сложность> ·
+<XP> XP`, затем сценарий и варианты. Варианты показываются со
сдвигом `offset = mission.id % (n−1) + 1`, чтобы верный ответ не всегда
был первым; порядок детерминирован (см. [SCORING.md](SCORING.md)).

Ответ → один из исходов:

| Исход | Экран |
|---|---|
| верно, впервые | `✅ Верно!` + XP, уровень `было → стало`, объяснение |
| верно, повторно | `🔁 Уже решено` — «XP не приносит» |
| неверно | `❌ Не совсем` + верный вариант и объяснение |
| по цели всё решено | `🏆 По цели пройдено всё (N/N)` + Skill Map |

Кнопки после миссии: «➡️ Следующая миссия», «📊 Skill Map», «🏠 Меню».

### Skill Map

Навыки, сгруппированные по категории, строки вида
`🟨 Python — уровень 2 · ▓▓▓▓▓░░░░░ 45% (до 3: 30 XP)`. Пусто →
«Навыки ещё не оценены».

Шкала: `⬛ 0`, `🟥 1`, `🟧 2`, `🟨 3`, `🟩 4`, `🟦 5`. Полоса
`progress_bar(percent, width=10)`, символы `▓` и `░`.

### Курсы и стажировки

Карточка курса: номер, название, платформа · уровень · формат, навыки,
описание. Стажировка: `название @ компания · уровень · локация ·
формат`, требования или описание. Название стажировки дополнительно
сокращается до 40 символов с многоточием.

Локация стажировки: `🌍 Удалённо` при `remote`, иначе город или
«Офис». Фильтр по городу сравнивается как есть — SQLite `lower()` не
работает с кириллицей.

Пагинация: страницы по 5 позиций, навигация появляется только если
страниц больше одной. У курсов кнопки-ссылки, у стажировок список
экраном.

### Резюме

Экраны согласия, ожидания, отчёта и ошибки — в
[разделе 5](#5-режим-резюме).

## 4. Состояния

```text
bot/sessions.py — sessions[max_user_id] = {
    "uid":       None,   # id профиля на платформе, кэш get-or-create
    "answers":   [],     # ответы текущей диагностики
    "resume":    False,  # ждём файл или текст резюме
    "welcomed":  False,  # приветствие уже отправлено
    "consent":   False,  # согласие на обработку ПД выдано
}
```

| Флаг | Ставит | Снимает | Сбрасывается при |
|---|---|---|---|
| `uid` | `ensure_user` | — | рестарте бота |
| `answers` | `assessment_answer` | завершение диагностики | рестарте, отмене |
| `resume` | `ask_resume`, `accept_consent` | отправка резюме, отмена, отказ, отзыв | рестарте |
| `welcomed` | `on_bot_started` | первый `/start` после приветствия | рестарте |
| `consent` | `accept_consent` | отказ, отзыв | рестарте |

**Живучесть:** состояние только в памяти. Рестарт обрывает начатую
диагностику и ожидание резюме; согласие и цель при этом сохранены в БД,
поэтому вопрос задастся заново. Один инстанс бота: два реплики не
разделяют состояние.

## 5. Режим резюме

```text
📄 Резюме (rs:start)
   │
   ├─ consent = false ──► 🔐 экран согласия (152-ФЗ)
   │                       [✅ Согласен] → POST /consent → экран ожидания
   │                       [❌ Не согласен] → «обрабатывать не буду»
   │                       [📄 Политика] → текст политики
   │
   └─ consent = true ───► экран ожидания
                           [❌ Отмена] [🚫 Отозвать согласие] [⬅️ Назад]
                           [⬅️ Назад]
                                    │
                        файл (PDF/DOCX/TXT) или текст
                                    │
                                    ▼
                              разбор и отчёт
                        [📄 Другое резюме] [🏠 Меню]
```

Принимаются PDF, DOCX и текстовые форматы (`.txt`, `.md`, `.rtf`,
`.csv`, `.json`, `.xml`, `.html`), лимит 5 МБ. Сканы без текстового
слоя не читаются — бот объясняет и просит текстовый вариант.

Ошибки при разборе: `[сервис анализа вернул ошибку]` на неожиданный
статус и `[формат не поддерживается, нужен PDF, DOCX или TXT]` на `422`.

Отчёт: соответствие направлению в процентах, при наличии GigaChat —
`🤖 Оценка: N/100` и вердикт, затем найденные навыки, недостающие,
сильные стороны, проблемы и до пяти советов.

Ключ «Отмена» по слову (`отмена`, `отменить`, `стоп`, `cancel`,
`/cancel`) работает в режиме ожидания.

## 6. Свободный текст и команды

Обрабатывается одним хендлером `fallback.on_text`:

| Ситуация | Реакция |
|---|---|
| ждём резюме | текст уходит в анализ; стоп-слово отменяет ожидание |
| иначе текст | «Я умею команды и кнопки меню 🙂» + главное меню |
| иначе команда | то же: подсказка с меню |

Команды: `/start` (связывает пользователя, показывает меню) и `/help`
(инструкция). Команда «Старт» в чате — та же, что `/start`.

Разбор файла идёт отдельным хендлером по наличию вложений и имеет
приоритет над текстовым.

## 7. Тон и оформление

- обращение на «ты», без канцелярита;
- эмодзи в каждом заголовке, числа и проценты видны сразу;
- короткие предложения, максимум две мысли на абзац;
- списки — маркером `•`, строки состояния — `✅` / `➕` / `💪` / `⚠️` / `💡`;
- **ошибки не виноват пользователь**: «Не получилось разобрать резюме:
  формат не поддерживается, нужен PDF, DOCX или TXT», а не «неверный
  файл»;
- **отказ — не тупик**: «Остальные разделы работают: Цель, Диагностика,
  Миссии, Skill Map, Курсы и Стажировки»;
- **отзыв согласия — нормальный шаг**: «Отозвать согласие можно в любой
  момент», без нотаций.

Подпись кнопок обрезается до 40 символов (`TEXT_LIMIT`) с многоточием —
иначе MAX ломает разметку на длинных названиях ролей и городов.

## 8. Ограничения MAX

| Ограничение | Как учтено |
|---|---|
| При добавлении бота приходят и `bot_started`, и `/start` | приветствие дедуплицируется флагом `welcomed` |
| Кнопка привязана к сообщению | ответ всегда идёт через `event.edit`, а не новым сообщением |
| Файлы приходят по временной ссылке | бот скачивает `payload.url` через `bot.download_bytes` |
| Свои payload'ы | все разделены `:` и используют короткие префиксы |
| Один обработчик на команду | `fallback.on_text` не дублирует `start` и `resume` |
| Ошибка в хендлере не должна рвать polling | `dp.errors()` логирует исключение, опрос продолжается |
| Длинные клавиатуры ломают разметку | `TEXT_LIMIT` и по одной кнопке в ряд для длинных списков |
