# Правила игры

Все формулы, пороги и порядки выбора — в одном месте. Каждое правило
указано с точкой входа в коде, чтобы его можно было сверить, а не
переоткрывать заново.

---

## 1. Опыт (XP)

`backend/app/services/skills.py`

```text
За верный ответ:   XP = mission.reward_xp + DIFFICULTY_BONUS[difficulty]
За неверный:       XP = 0
```

| Сложность | Бонус |
|---|---|
| `easy` | +0 |
| `medium` | +10 |
| `hard` | +20 |

`reward_xp` задаётся у миссии в контенте (см. [CONTENT.md](CONTENT.md)).
Начисляет `SkillService.apply_mission_result`, пишет строку в `attempts`.

**Повторное решение не платит.** `MissionService.submit_answer` сначала
ищет `latest_correct_attempt`; если верная попытка уже есть, возвращается
`already_solved: true` с нулевым XP и новой записи в `attempts` не
создаётся. Так цикл «угадал один раз — качаешься вечно» невозможен.

Ошибка не откатывает уже набранный опыт: попытка с `is_correct=false`
сохраняется как есть, XP не начисляется.

## 2. Уровни навыка

Уровень — функция накопленного опыта, а не отдельный счётчик.

```text
LEVEL_THRESHOLDS = (0, 100, 250, 450, 700, 1000)
level = количество порогов, не превосходящих experience
```

| Уровень | Порог опыта |
|---|---|
| 0 | 0 |
| 1 | 100 |
| 2 | 250 |
| 3 | 450 |
| 4 | 700 |
| 5 | 1000 |

`MAX_LEVEL = 5` — выше уровня не растёт.

```text
progress_for_level = (experience − порог_текущего) / (порог_следующего − порог_текущего) × 100
```

Процент округляется до одного знака. На максимальном уровне `progress`
всегда `100.0`, а `next_level_xp` — `null`. Иначе
`next_level_xp = порог_следующего − experience`.

Диагностика **не понижает** прогресс: `set_initial_skill` берёт
`max(текущий опыт, порог_уровня)`.

## 3. Соответствие целевой роли (`match_percent`)

`backend/app/services/gap_analysis.py`

Каждое требование роли взвешивается по `importance`:

```text
readiness = min(current_level / required_level, 1.0)     # required_level = 0 → 1.0
match_percent = round(Σ(readiness × importance) / Σ(importance) × 100)
```

Если у роли нет требований, процент считается `100`.

| Поле | Смысл |
|---|---|
| `current_level` | уровень пользователя по навыку |
| `required_level` | требуемый уровень роли |
| `gap` | `max(0, required_level − current_level)` |
| `importance` | вес требования, обычно `0.35…0.9` |
| `is_mandatory` | обязательное ли требование (влияет на порядок выдачи) |

`gap > 0` — разрыв. `items` сортируются по убыванию `gap`, затем по
имени навыка, поэтому порядок стабилен между запусками.

Если целевая роль не выбрана, `role` и `match_percent` — `null`, а
`summary` предлагает выбрать цель.

## 4. Выбор следующей миссии

`MissionService.get_next_mission`

**Требуется целевая роль.** Без неё — `status: "no_goal"`.

Пул кандидатов — только миссии по навыкам из требований роли. Всё
остальное (миссии по другим навыкам) в выдачу не попадает.

Приоритет — лексикографический, первый же признак решает:

| № | Признак | Что значит |
|---|---|---|
| 1 | `0`, если `gap > 0`, иначе `1` | сначала навыки с пробелом |
| 2 | `0`, если `is_mandatory`, иначе `1` | среди пробельных — обязательные |
| 3 | `−(gap × importance)` | тем больше разрыв и вес, тем раньше |
| 4 | `1`, если уже была ошибка, иначе `0` | непробованные раньше ошибочных |
| 5 | `DIFFICULTY_RANK`: `easy` 0, `medium` 1, `hard` 2 | от лёгких к сложным |
| 6 | `mission.id` | детерминированность при полном равенстве |

Последний признак делает выбор воспроизводимым: при одинаковых
приоритетах всегда одна и та же миссия, а не случайная.

Статусы ответа:

| `status` | Когда | Что показывает бот |
|---|---|---|
| `ok` | есть нерешённые миссии | сама миссия |
| `no_goal` | не выбрана целевая роль | «сначала выбери цель» |
| `all_done` | все миссии роли решены верно | «по цели пройдено всё» |

`done` — сколько миссий роли решено верно, `total` — сколько всего
миссий по навыкам роли.

Ранее ошибочные миссии не исключаются: они просто идут после
непробованных, чтобы вернуться к ним после освоения нового.

## 5. Порядок показа вариантов ответа

`bot/handlers/missions.py`, `_display_order`

Сдвиг детерминированный, чтобы верный ответ не всегда стоял первым:

```text
offset = mission.id % (len(options) − 1) + 1
порядок = options[offset:] + options[:offset]
```

Одна миссия всегда показывается в одном и том же порядке — переугадать
заученную схему нельзя. При одном варианте порядок не меняется.

Ответ уходит по `option_id`, а не по позиции, поэтому сдвиг не ломает
проверку. Номера на кнопках — позиции в **показанном** порядке, полный
текст вариантов выводится сообщением.

## 6. Рекомендации

`backend/app/services/recommendations.py`

Требования к навыкам берутся из целевой роли, а если её нет — из
`DIRECTION_REQUIRED_SKILLS` по `user.direction`:

| Направление | Обязательные навыки |
|---|---|
| `backend` | Python, SQL, Git, Алгоритмы и структуры данных, Docker |
| `frontend` | JavaScript, HTML/CSS, React, Git |
| `data` | Python, SQL, Pandas, Machine Learning |
| `design` | Figma, UI/UX |
| `qa` | Testing, SQL, Git |
| `analytics` | SQL, Pandas, Python |

Неизвестное или пустое направление — требований нет, рекомендаций нет.

Пробелы (`_gaps`) — те же `gap > 0`, что и в gap-анализе.

**Курсы** ранжируются по числу пересекающихся с пробелами навыков, затем
по стоимости: больше совпадений — выше, при равенстве дешевле — выше.
Каталог пустых совпадений отбрасывается: если пробелов нет, возвращается
пустой список, а не весь каталог.

**Стажировки** ранжируются по сумме:

```text
score = |навыки стажировки ∩ пробелы| + (3, если направление совпало с направлением роли)
```

Направление стажировки сравнивается с направлением целевой роли, иначе
с `user.direction`. Бонус за направление (3) сопоставим с тремя
закрытыми пробелами: это делает профильные стажировки приоритетнее
смежных, но не абсолютно.

## 7. Сводка формул

| Величина | Формула | Код |
|---|---|---|
| XP за миссию | `reward_xp + бонус_сложности`, только за верный ответ; повторно — `0` | `services/skills.py` |
| Уровень навыка | число порогов `≤ experience` | `services/skills.py` |
| Прогресс уровня | `(xp − порог) / (порог₊₁ − порог) × 100` | `services/skills.py` |
| `match_percent` | `round(Σ(readiness × importance) / Σ(importance) × 100)` | `services/gap_analysis.py` |
| Следующая миссия | 6 признаков: пробел → mandatory → gap×importance → не пробована → сложность → id | `services/missions.py` |
| Порядок вариантов | `offset = id % (n − 1) + 1` | `bot/handlers/missions.py` |
| Курсы | пересечение с пробелами, затем цена по возрастанию | `services/recommendations.py` |
| Стажировки | пересечение с пробелами + 3 за совпадение направления | `services/recommendations.py` |
