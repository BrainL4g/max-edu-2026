# Контент

Справочник для того, кто ведёт наполнение: формат записей, требования к
миссиям, шкала сложности, проверка ссылок и обновление уже развёрнутой
базы.

**Источник правды — `backend/app/seed.py`.** Всё, что описано ниже,
берётся оттуда; при изменении контента правьте этот файл.

---

## 1. Где что лежит

| Таблица | Список в `seed.py` | Кто пользуется |
|---|---|---|
| `skills` | `SEED_SKILLS` | диагностика, Skill Map, gap-анализ, рекомендации |
| `missions`, `mission_options` | `SEED_MISSIONS` | миссии по ролям |
| `courses`, `course_skills` | `SEED_COURSES` | рекомендации курсов |
| `internships`, `internship_skills` | `SEED_INTERNSHIPS` | рекомендации стажировок |
| `roles`, `role_skills` | `SEED_ROLES` | цели, пул миссий, match_percent |

Тематический набор вопросов диагностики лежит отдельно:
`backend/app/services/assessment.py`, `ASSESSMENT_QUESTIONS` — он не
записывается в базу, а отдаётся из кода.

Обязательные навыки по направлениям:
`backend/app/services/recommendations.py`, `DIRECTION_REQUIRED_SKILLS`.

## 2. Формат записей

### Навык

```python
("Название", "Категория", "Описание")
```

| Поле | Требование |
|---|---|
| Название | уникально, как в `SEED_SKILLS`; используется для поиска в резюме |
| Категория | одна из существующих: «Программирование», «Данные», «Инструменты», «QA», «Дизайн», «Soft skills» |
| Описание | одно предложение, чем навык полезен |

Название навыка должно совпадать с ключом в `SKILL_ALIASES`
(`resume_analysis.py`) и уметь распознаваться в резюме. Переименование
ломает и поиск в резюме, и существующие записи в `user_skills` по
навыку, если он уже в базе.

### Миссия

```python
{
    "skill": "Python",              # навык, должен быть в SEED_SKILLS
    "difficulty": "easy",           # easy | medium | hard
    "scenario": "Условие задачи и вопрос",
    "options": [
        ("Текст варианта", False),  # неверный
        ("Текст верного", True),   # ровно один верный
    ],
    "explanation": "Почему так, а не иначе",
    "reward_xp": 20,
}
```

| Поле | Требование |
|---|---|
| `skill` | точное название из `SEED_SKILLS` |
| `options` | 2–5 вариантов, **ровно один** с `is_correct=True` |
| `explanation` | обязателен: без него верный ответ ничему не учит |
| `reward_xp` | 20 для `easy`, 30 для `medium`, 35–50 для `hard` |

### Роль

```python
{
    "name": "Backend Junior",       # уникально
    "direction": "backend",         # совпадает с user.direction
    "level": "junior",
    "description": "Чем эта роль отличается",
    "skills": [
        ("Python", 3, 0.9, True),   # навык, уровень, importance, is_mandatory
        ("Docker", 1, 0.4, False),
    ],
}
```

`level` — от `0` до `5` по шкале навыков, а не по seniority: «junior»
может требовать `level 3`, это шкала сложности, а не должность.

### Курс

```python
{
    "title": "Название",
    "description": "Что внутри",
    "platform": "Stepik",
    "url": "https://...",
    "level": "beginner",            # beginner | intermediate | advanced
    "category": "Программирование",
    "cost": 0.0,                    # 0.0 для бесплатных
    "format": "online",             # online | offline
    "skills": ["Python", "Git"],
}
```

### Стажировка

```python
{
    "title": "Стажировка Python-разработчик",
    "company": "Яндекс",
    "description": "Что делает стажёр",
    "url": "https://...",
    "level": "beginner",
    "city": "Москва",
    "remote": False,
    "format": "office",             # office | remote
    "requirements": "Базовый Python, SQL",
    "direction": "backend",         # для бонуса в ранжировании
    "skills": ["Python", "SQL"],
}
```

## 3. Критерии хорошей миссии

**Вопрос должен быть решаемым.** Если сомневаетесь в правильном
ответе — миссия не готова.

**Неверные варианты должны быть правдоподобными.** Хорошая неверная
ошибка — та, в которую попадает человек, не знающий темы:

```python
# плохо: варианты, которые отсеиваются без размышления
("Принтануть результат", False)
("Вызвать метод sum() у диапазона", False)
("Сложить числа от 1 до n", True)

# хорошо: каждая ошибка — реальное заблуждение
("print(sum(n))", False),                              # sum от числа
("print(range(1, n).sum())", False),                    # sum у range
("print(n + 1)", False),                                # арифметика вместо цикла
("print(sum(range(1, n + 1)))", True),
```

Проверка: закройте верный ответ и спросите, ошибётся ли на остальных
вариантах человек, который тему знает. Если нет — вариант слишком
очевидно неверный, пользы от него нет.

**Один верный вариант.** Два верных — проверка всегда проходит; ни
одного — задача нерешаема.

**Объяснение обязательно.** Оно показывается после ответа и должно
объяснять *почему*, а не повторять условие:

```python
"explanation": "range(4) даёт 0..3, квадраты: 0, 1, 4, 9."
```

**Сценарий — про контекст, а не про синтаксис.**

```python
# плохо
"Что вернёт [x ** 2 for x in range(4)]?"

# хорошо
"Нужно выбрать первые четыре квадрата, не создавая список вручную. Что вернёт [x ** 2 for x in range(4)]?"
```

**Разнообразие.** Одна тема — не больше трёх миссий подряд. Иначе
пользователь упирается в стену однообразия.

**Порядок в `SEED_MISSIONS` не влияет на выдачу.** Миссии выбираются по
приоритету из gap-анализа, а не по порядку в файле (см.
[SCORING.md](SCORING.md#4-выбор-следующей-миссии)). Порядок в файле —
лишь порядок чтения при первом наполнении.

## 4. Шкала сложности

| `difficulty` | Бонус к XP | Ориентир |
|---|---|---|
| `easy` | +0 | синтаксис, одна концепция, гуглится за минуту |
| `medium` | +10 | несколько концепций сразу, типичная рабочая задача |
| `hard` | +20 | граничный случай, требует понимания, а не запоминания |

`reward_xp` задаётся отдельно и определяет основную награду. Сложность
добавляет бонус и служит фильтром при выборе следующей миссии.

**Шкала уровней навыка** (0–5, пороги в `LEVEL_THRESHOLDS`):

| Уровень | Ориентир |
|---|---|
| 0 | не встречал |
| 1 | базовый синтаксис, простые скрипты |
| 2 | функции, классы, структуры данных языка |
| 3 | проекты с библиотеками, тестами, типизацией |
| 4 | архитектурные решения, производительность, отладка |
| 5 | эксплуатация, профилирование, вклад в инструменты |

Требования ролей (`required_level`) стоит выставлять по этой шкале:
`Backend Junior` с `Python: 3` означает «уверенно пишет проекты», а не
«знает синтаксис».

## 5. Проверка ссылок

Ссылки на курсы и стажировки **никем не проверяются**: `url` хранится
как есть и отдаётся кнопкой. Мёртвая ссылка уедет вместе с каталогом и
будет выглядеть как ошибка платформы.

### Перед добавлением записи

1. Открыть `url` и убедиться, что ведёт на материал, а не на
   заглушку (`example.com`, `yandex.ru/jobs`, `/search`).
2. Для поисковых ссылок (например, `youtube.com/results?search_query=…`)
   предпочесть конкретную страницу: выдача меняется и персональные
   рекомендации засорятся чужими видео.
3. Для платных курсов указать реальную `cost > 0` — иначе в подборке
   бесплатного окажется платное.
4. Проверить, что площадка доступна из РФ.

### Регулярная проверка

Скрипта автоматической проверки в проекте нет. Разумный интервал —
раз в квартал, вручную:

```bash
# собрать все ссылки из контента
python -c "
import sys; sys.path.insert(0, 'backend')
from backend.app.seed import SEED_COURSES, SEED_INTERNSHIPS
for group, items in (('course', SEED_COURSES), ('internship', SEED_INTERNSHIPS)):
    for item in items:
        print(group, item['url'])
"
```

Затем открыть список и проверить каждую ссылку. Удалённую заменить
на актуальную, а не удалять: пустая выдача по направлению хуже, чем
устаревшая ссылка.

## 6. Обновление уже развёрнутой базы

`seed_database` **идемпотентна частично**: если в базе есть хотя бы один
навык, повторный вызов **не добавит** новые записи, а только обновит
`courses.cost` для платных и досоздаст роли, если их нет.

```python
if db.scalar(select(func.count(Skill.id))) or 0:
    db.execute(update(Course).where(Course.cost > 0).values(cost=0.0))
    db.commit()
    return _seed_roles_if_empty(db)
```

То есть изменение `SEED_COURSES` на работающей базе **не подхватится**.

### Вариант 1: скрипт обновления (рекомендуется)

Написать одноразовый скрипт рядом с `scripts/`, который правит нужные
таблицы по `id` или по имени, и запустить один раз:

```python
# scripts/update_content.py — набросок
from sqlalchemy import select
from backend.app.database.session import SessionLocal
from backend.app.domain import Course

db = SessionLocal()
course = db.scalar(select(Course).where(Course.title == "Название курса"))
if course is not None:
    course.url = "https://..."
    course.cost = 0.0
    db.commit()
```

Так обновление не трогает остальные записи и не требует пересоздания
базы.

### Вариант 2: чистая база

```bash
docker compose down
docker volume rm skillquest_data
docker compose up -d --build
```

**Теряет всё**: профили, ответы диагностики, попытки, резюме,
согласия, токены. Учётки создаются заново, все сессии сбрасываются.
Годится для демонстрации, не для рабочих данных.

### Осторожно: повторный сид обнуляет цены

`seed_database` на непустой базе выполняет побочный эффект:

```python
db.execute(update(Course).where(Course.cost > 0).values(cost=0.0))
```

Это обнуляет **все** платные курсы, а не приводит цены к данным из
`SEED_COURSES`. Следствия:

- не запускайте `seed_database` на базе с выставленными ценами без
  нужды;
- если цены заданы, восстанавливайте их скриптом обновления из
  варианта 1;
- причина в том, что сид рассчитан на демо-стенд, где все курсы
  бесплатные. Для рабочих данных правильнее вынести цены из
  демо-контента.

### Что нужно помнить

| Таблица | Последствие удаления |
|---|---|
| `skills` | каскадом уходят `user_skills`, `missions` — Skill Map и пул миссий теряются |
| `missions` | каскадом уходят `mission_options` и `attempts` — история и XP теряются |
| `roles` | `users.target_role_id` станет `NULL` — цель у всех сброшена |
| `courses`, `internships` | прогресс и согласия не затрагиваются |

**Никогда не удаляйте `skills`, `missions` и `roles` на базе с
пользователями.** Добавляйте и меняйте; удаление — только на чистой
базе.

**Миграциями контент не правится.** Alembic — для схемы, не для
содержимого. Данные живут в `seed.py` и скриптах обновления.

### Новые направления

1. добавить роль с новым `direction` в `SEED_ROLES`;
2. добавить обязательные навыки в `DIRECTION_REQUIRED_SKILLS`;
3. добавить вопросы диагностики с этим `direction` в
   `ASSESSMENT_QUESTIONS` — иначе диагностика покажет все вопросы;
4. проставить `direction` у стажировок — иначе не будет бонуса в
   ранжировании.

Пропустив любой шаг, направление заработает частично: роли появятся, а
вопросы и рекомендации окажутся обшими.
